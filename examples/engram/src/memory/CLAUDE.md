# Memory tiers — invariants

- **All writes go through the tier facades, never raw SQL**: events via `RecallStore.appendEvent`, archival via `ArchivalMemory.insert/update/delete`, core blocks via `CoreMemory.append/replace`. Each facade owns its side effects (FTS projection, history audit, entity relink, CAS version bump); bypassing one silently corrupts derived state.
- **Scope enters payloads in exactly one place per store.** Callers pass a `Scope`; identity keys found in metadata are stripped with a warning (`stripIdentityKeys`). Never add a second path.
- **Reads and writes have different scope semantics** (mem0 parity). Writes store the full thread identity with absent keys normalized to `""`, and write-side dedup is exact on all three columns. Reads filter **only on the keys the caller supplies** (`scopeFilter`): `archival_search`, prefetch, and extraction Phase 1 pass `{userId}` alone so memories are shared across the user's agents. A supplied `""` matches exactly — it never wildcards. Do not "fix" a read path back to exact three-column equality; that made the curator agent blind to every user memory.
- **Append subscriptions are a view, never a write path.** `RecallStore.subscribe` fires *after* `appendEvent`'s transaction commits, so a subscriber can never observe an event that rolls back; a throwing subscriber is warned about and ignored rather than failing the append. Callers (SSE) must release their subscription in a `finally` — a disconnected client that stays subscribed leaks.
- **Extraction is serialized per thread** under the `extract:<threadId>` lock namespace, and the `extracted_seq` watermark is monotonic (`max(extracted_seq, ?)`). Fire-and-forget callers may overlap requests freely; the lock and the monotonic write are what prevent duplicate LLM calls and watermark regression.
- **Every archival mutation writes a `memory_history` row** with before/after values; deletes keep their history (`is_deleted = 1`). If you add a mutation, add its audit row in the same transaction.
- **The extraction pipeline is phased and ADD-only** (`extraction.ts`): only Phase 2 (the LLM call) may throw; every other phase degrades per-item with a warning. Reconciliation (UPDATE/DELETE decisions by an LLM) lives in `reconcile.ts`, an *offline* job — never in this hot path.
- **The extraction reader Worker reads and nothing else.** `reader-client.ts`/`reader-worker.ts` move Phase 1's candidate scan off the main thread when `ENGRAM_EXTRACTION_WORKER=on`. The Worker opens the database read-only (or deserializes a snapshot for `:memory:`, which no second connection can reach), never embeds (the main thread passes the vector, so no credential crosses the boundary), and never writes — every write stays on the main thread under the `extract:` lock, which is what keeps the in-process single-writer invariant true. It is an optimization, never a dependency: any failure falls back to the in-thread scan with a warning.
- **Reconciliation plans before it writes, and never bypasses the facade.** `reconcile.ts` is the only place a model may rewrite or delete a memory. It clusters by raw cosine over stored vectors (not `search()`, whose blended score is not comparable between two stored memories), applies nothing unless asked, withholds the WHOLE pass when it wants more than `DELETE_APPROVAL_THRESHOLD` deletes, never empties a cluster, and mutates through `ArchivalMemory.update`/`delete` with actor `reconcile` so each change re-embeds, reindexes, relinks and audits. Memories with no vector are skipped and counted, never clustered by a lexical guess.
- **Temporal grounding**: extracted memories resolve relative time against the conversation's observation date. If you touch the extraction prompt, keep the Observation Date vs Current Date separation.
- **Embeddings are optional.** `embedder === null` is a supported mode (FTS + entity only). Any new retrieval feature must work — perhaps worse, but honestly — without vectors.
- **Search order is fixed**: expiration filter → semantic threshold gate → THEN keyword/entity boosts → adaptive divisor. Boosts must never resurrect a semantically gated-out candidate (mem0's deliberate design).
- **Compaction never mutates the log.** `compaction.ts` distills events before the verbatim tail into the `compactions` table and hands the result to `renderUserMessage` like prefetch — the canonical events stay intact and `recall_search` still reaches them (constitution I). It is idempotent per `(thread_id, up_to_seq)`, re-compacts only once the boundary advances by `COMPACT_STRIDE`, carries the previous distillate into the next round so nothing is dropped between them, and degrades to the plain elision marker on failure.
